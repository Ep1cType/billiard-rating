# Бильярдный рейтинг

Статический сайт для турнирной таблицы по бильярду. Работает на GitHub Pages,
без сервера и без базы данных — все результаты хранятся в одном файле
`data/db.json` внутри репозитория.

- **Публичная часть** (`index.html`, `tournaments.html`, `tournament.html`) —
  читает `data/db.json` напрямую как статический файл.
- **Админка** (`admin.html`) — единственная страница, которая пишет данные.
  Она обновляет `data/db.json` через GitHub API, используя ваш личный токен
  доступа. После сохранения GitHub Pages пересобирает сайт — обычно это
  занимает 30–90 секунд.

---

## 1. Настройка (один раз)

### 1.1. Создайте репозиторий

1. Создайте новый репозиторий на GitHub (публичный — GitHub Pages для
   приватных репозиториев тоже работает, но требует платный план).
2. Загрузите в него все файлы из этой папки, сохранив структуру каталогов.

### 1.2. Включите GitHub Pages

Settings → Pages → Source: **Deploy from a branch** → Branch: **main** / `(root)` → Save.
Через пару минут сайт будет доступен по адресу вида
`https://ваш-логин.github.io/название-репозитория/`.

### 1.3. Укажите репозиторий в конфиге

Откройте `js/config.js` и замените:

```js
export const GITHUB_OWNER = 'ВАШ_ЛОГИН';
export const GITHUB_REPO = 'НАЗВАНИЕ_РЕПОЗИТОРИЯ';
```

на реальные значения (то, что стоит после `github.com/` в адресе репозитория).
Закоммитьте изменение.

### 1.4. Создайте токен доступа

1. [github.com/settings/tokens?type=beta](https://github.com/settings/tokens?type=beta) → **Generate new token**.
2. Repository access → **Only select repositories** → выберите ваш репозиторий.
3. Permissions → Repository permissions → **Contents** → **Read and write**.
4. Generate token, скопируйте значение (оно показывается один раз).

Это же самое можно сделать прямо на странице `/admin.html` — там есть
пошаговая инструкция со ссылкой.

Токен даёт доступ только к выбранному репозиторию, а не ко всему аккаунту.
Он сохраняется в localStorage вашего браузера — не публикуйте его и не
вводите на чужом компьютере.

## 2. Как пользоваться

**Добавить турнир:** зайдите на `/admin.html`, один раз введите токен,
затем на форме укажите название, дату, тип турнира и для каждого сыгравшего
игрока — очки. Существующих игроков можно выбрать из подсказки при вводе
имени (так же исключаются дубли из-за опечаток); новое имя автоматически
станет новым игроком. Ниже формы виден предпросмотр того, как разложатся
места. Кнопка «Сохранить турнир» пишет изменения прямо в репозиторий.

**Посмотреть результаты:** главная страница — общий рейтинг (сумма очков
по 12 лучшим турнирам каждого игрока, доли мест — как в турнире). Страница
«Турниры» — список всех турниров со ссылкой на результаты каждого.

## 3. Формат данных (`data/db.json`)

```json
{
  "players": [
    { "id": "p_m3x1a2b9c", "name": "Иван Петров" }
  ],
  "tournaments": [
    {
      "id": "t_m3x1c7d2e",
      "name": "Зимний мини-турнир",
      "date": "2026-01-15",
      "type": "mini",
      "results": [
        { "playerId": "p_m3x1a2b9c", "points": 120 }
      ]
    }
  ]
}
```

`type` — один из `mini`, `masters`, `grand_slam` (подписи задаются в
`js/ranking.js`, там же меняется число учитываемых турниров `TOP_N`, если
захотите взять не 12, а другое количество).

Место (`place`) нигде не хранится — оно всегда считается на лету из очков,
и в турнире, и в общем рейтинге, так что данные не могут «разойтись».

Файл можно в крайнем случае поправить и вручную — прямо в веб-редакторе
GitHub, это всегда работает как запасной способ.

---

## 4. Что не реализовано в этой версии

- Редактирование и удаление уже сохранённых турниров через админку —
  сейчас это делается прямым редактированием `data/db.json` на GitHub.
- Страницы отдельных игроков (сейчас имя есть только в таблицах).
- Многопользовательская админка с разными токенами/ролями.

Это осознанно оставлено за скобками первой версии, чтобы не раздувать
объём. Всё это можно добавить позже — дайте знать, если что-то из этого
нужно в первую очередь.

## 5. Тесты логики подсчёта

`tests/test-ranking.mjs` проверяет подсчёт мест и топ-12 агрегации.
Если у вас установлен Node.js:

```bash
node tests/test-ranking.mjs
```

---

## 6. Переезд на React/NestJS в будущем

Вся логика подсчёта (`js/ranking.js`) не завязана на DOM и на источник
данных — она просто получает `players`/`tournaments` и возвращает готовые
места. Её можно перенести в NestJS-сервис почти без изменений, а
`data/db.json` при переезде естественно превращается в таблицы
`players`/`tournaments`/`results` в базе данных.
